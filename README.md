# ПромоСтарт — честный генератор победителя

Инструмент для розыгрышей призов в соцсетях. Вы задаёте диапазон номеров участников, инструмент выбирает победителя и выдаёт **ссылку проверки**, по которой любой участник независимо пересчитает результат и убедится, что розыгрыш не подкручен.

**Живая демонстрация:** https://yaroslava-111.github.io/winner-picker/

Этот файл написан для человека, который впервые видит репозиторий: как установить проект с нуля, запустить, проверить, опубликовать, обновить и что делать, если что-то не работает.

---

## 1. Что делает сервис и для кого он создан

Главная проблема розыгрыша в соцсетях — недоверие. Организатор говорит «победил номер 42», а участники не могут это проверить и подозревают подтасовку.

Сервис закрывает именно это: вместе с номером победителя он публикует **seed** — случайное значение, из которого номер был вычислен. По seed результат воспроизводится кем угодно и в любой момент. Если организатор подменит победителя, проверка это покажет.

Для кого:

- **SMM-специалисты и администраторы сообществ** — проводят розыгрыши среди подписчиков;
- **организаторы прямых эфиров** — анимация прокрутки номеров рассчитана на показ в эфире;
- **небольшие магазины и мастерские** — разыгрывают призы среди покупателей.

### Возможности

- **Два способа задать участников** — режим «Диапазон» (поля «От номера» и «До номера») или режим «Количество» (участники нумеруются с 1).
- **Розыгрыш нескольких призов подряд** — номера не повторяются, пока не закончится пул; на экране счётчики «осталось» и «выиграло».
- **Анимация прокрутки номеров** — удобно показывать в прямом эфире.
- **Ссылка проверки** — готовая ссылка, по которой результат пересчитывается независимо.
- **Кнопка «Скопировать текст результата»** — готовый текст для поста вместе со ссылкой проверки.
- **История текущего запуска** — список всех выпавших номеров.
- **Полностью локальная работа** — данные никуда не отправляются, интернет нужен только для открытия страницы.

## 3. Системные требования

| Что нужно | Версия | Зачем |
|---|---|---|
| Браузер Chrome, Edge, Firefox или Safari | Chrome/Edge 90+, Firefox 90+, Safari 15+ | Сам сервис |
| Git | любая актуальная | Склонировать репозиторий |
| Python | 3.8 и новее | Только для локального сервера (способ 2) |

Операционная система — любая: Windows, macOS, Linux. Сервер, база данных, Node.js и сборка не нужны.

Отдельное требование к браузеру: нужен **Web Crypto API** (`crypto.getRandomValues` и `crypto.subtle`). Он есть во всех перечисленных версиях, но `crypto.subtle` доступен только на страницах, открытых по `https://` или с адреса `localhost`. Для случая, когда он недоступен, в проекте предусмотрена запасная реализация SHA-256 на JavaScript.

## 5. Запуск

### Способ 1. Открыть файл в браузере

Откройте `index.html` двойным щелчком.

### Способ 2. Локальный сервер (рекомендуется)

Так браузер считает страницу безопасным контекстом и использует встроенную криптографию вместо запасной реализации. Из папки проекта:

```bash
python -m http.server 8000
```

Если команда `python` не найдена:

```bash
python3 -m http.server 8000
```

Откройте в браузере:

```text
http://localhost:8000
```

Остановить сервер — `Ctrl + C` в терминале.

## 6. Проверка работоспособности

Автотестов в проекте нет — главный сценарий проверяется вручную за три минуты. Он же и есть главная проверка смысла сервиса: результат должен воспроизводиться.

### 6.1. Главный пользовательский сценарий

1. Откройте страницу любым способом из раздела 5.
2. Оставьте выбранным режим **«Диапазон»**, введите `1` в поле «От номера» и `100` в поле «До номера», нажмите **«Создать розыгрыш»**.
   **Ожидаемый результат:** открылся экран розыгрыша, вверху написано «Участники 1 – 100», счётчик «осталось» показывает `100`.
3. Нажмите **«Разыграть приз»**.
   **Ожидаемый результат:** номера прокручиваются, затем останавливаются на одном; он появляется в блоке «Победитель №…», счётчик «осталось» становится `99`, «выиграло» — `1`.
4. Нажмите **«Разыграть приз»** ещё раз.
   **Ожидаемый результат:** выпал **другой** номер, в блоке «Выпавшие номера» теперь два разных значения.
5. Скопируйте значение поля **«Seed проверки»** кнопкой рядом с ним.
6. Нажмите **«Открыть страницу проверки»**, вставьте seed, укажите `1` и `100` и перечислите оба выпавших номера через запятую, нажмите **«Проверить»**.
   **Ожидаемый результат:** проверка подтвердила совпадение номеров.
7. Повторите шаг 6, но замените один из номеров на любой другой.
   **Ожидаемый результат:** проверка сообщила о несовпадении — значит, подмену результата она действительно ловит.

Если шаги 6 и 7 дали разный результат, механизм честности работает правильно.

### 6.2. Как устроена честность

- Seed — 256 бит из `crypto.getRandomValues`, а не из `Math.random()`.
- Номер каждого приза вычисляется как `SHA-256(seed + ":" + номер приза)`; полученное число определяет позицию в оставшемся пуле.
- Один и тот же seed с тем же диапазоном всегда даёт ту же последовательность победителей — поэтому результат и воспроизводим.
- Ссылка проверки имеет вид:

  ```text
  https://yaroslava-111.github.io/winner-picker/?seed=СЮДА_SEED&from=1&to=100&winners=42,17
  ```

## 11. Резервное копирование

Постоянного хранилища у сервиса нет: ни базы данных, ни записи в браузере. Выпавшие номера и seed живут только в открытой вкладке и исчезают при её перезагрузке или закрытии.

Поэтому резервная копия здесь — это **сохранённый результат розыгрыша**, и делать её нужно сразу:

1. Сразу после розыгрыша нажмите **«Скопировать текст результата»**.
2. Вставьте текст туда, где он останется: в пост с итогами, в рабочий чат, в файл.
3. Отдельно сохраните **ссылку проверки** — именно она позволит пересчитать результат позже.

Рекомендация для спорных ситуаций: публикуйте seed и ссылку проверки в том же посте, где объявляете победителя. Тогда у участников есть всё необходимое, чтобы проверить розыгрыш самостоятельно.

## 12. Известные ограничения

- **Максимум 1 000 000 участников** в одном розыгрыше.
- **История хранится только в текущей вкладке.** Перезагрузка страницы начинает новый розыгрыш с новым seed; восстановить прежний пул нельзя.
- **Схема «commit-reveal» не реализована.** Сейчас seed публикуется вместе с результатом. Недобросовестный организатор теоретически может провести несколько розыгрышей и опубликовать понравившийся. Полная защита — публиковать хэш seed **до** розыгрыша, а сам seed после; этой возможности в текущей версии нет.
- **Нет списка имён участников** — сервис работает только с номерами. Соответствие «номер → человек» организатор ведёт отдельно.
- **Нет защиты от повторного открытия страницы** несколькими людьми: каждый получает свой независимый seed.
- **Нет экспорта истории в файл** — только копирование текста результата.

## 13. Если что-то не работает

| Что вы видите | Причина | Что сделать |
|---|---|---|
| Кнопка розыгрыша не реагирует | Пул исчерпан — разыграны все номера | Нажмите «Новый розыгрыш» или «Изменить участников» |
| Ошибка при вводе диапазона | Начало больше конца или поле пустое | Проверьте, что «от» меньше «до» и оба поля заполнены |
| Проверка сообщает «не совпадает», хотя номера верные | Указан не тот диапазон или не тот seed | Сверьте `from`, `to` и seed с теми, что были во время розыгрыша — они должны совпадать полностью |
| Анимация идёт, но номер не появляется | Ошибка в JavaScript | `F12` → вкладка **Console**, прочитайте красное сообщение |
| Страница открыта по `file://`, расчёт идёт медленнее | Недоступен `crypto.subtle`, работает запасная реализация SHA-256 | Запустите локальный сервер (раздел 5) или откройте опубликованную версию по `https://` |
| `python: command not found` | Python не установлен или называется `python3` | Выполните `python3 -m http.server 8000` или установите Python с https://www.python.org/downloads/ |
| `Address already in use` | Порт 8000 занят | Запустите на другом порту: `python -m http.server 8080` |

### Где смотреть журнал ошибок

Своих файлов журнала у сервиса нет. Все ошибки видны в браузере: `F12` → вкладка **Console**.
